# 0.1.2：质量实验记录（E1 / E2）

## 背景

0.1.1 的 50 轮人工盲测（21:10，真心赢 68%）暴露出三类失败：编造、太短、关键事实没被注入。
E1/E2 分别验证「太短」和「编造」的修法。两轮实验都在本地 AstrBot 4.29.1 上跑，
每轮两个全新 WebChat 会话、同一份 `validation_50.jsonl`、50 轮。

## E1：关掉节奏后处理

配置：`aux.rhythm_postprocess=false`（其余同 0.1.1）。

| | 基线 | live |
|---|---:|---:|
| 平均回复字数 | 39.4 | 29.1 |
| 价格 | ¥0.5165 | ¥0.3899（-24.5%） |

**结论：无效。** 关掉后处理并没有让回复变长，反而更短。原因：真正驱动短回复的是
`rhythm.compute()` 注入的「〔节奏：N 字内〕」提示，后处理只是兜底。要解决太短，必须
关掉整个节奏模块。

## E2：节奏模块整体关闭 + 三个代码修正

代码（0.1.2）：

1. **问句不再生成事实**（`l2._is_question`）：`上次说的阿哲，是不是搞摄影的` 不会再写出
   “阿哲是摄影师”；`不吃什么吗` 这类问句也不再变成 habit 线索。
2. **稳定前缀加边界句**：`【边界】只依据已知线索和最近对话回答；不知道就直说不知道，不要编造…`
   （常量，只占一个缓存块）。
3. **事实优先**：`type_bonus` 里 habit 0.35 / fact 0.25 / emotion 0.1，让「不吃香菜」压过
   「最近生气」。
4. 顺手修了一个测量 bug：影子模式的回复以前也会被节奏后处理改写（用户看到的和记下来的不一致），
   现在影子路径原样记录。

配置：`aux.rhythm=false` + `aux.rhythm_postprocess=false`。

| | 基线 | live |
|---|---:|---:|
| 平均回复字数 | 87.8 | 94.4 |
| 非缓存输入 | 99,218 | 104,718 |
| 缓存输入 | 500,608 | 347,904 |
| 总输入 | 599,826 | 452,622（-24.5%） |
| 输出 | 4,976 | 6,501 |
| 价格 | ¥0.4885 | ¥0.4354（-10.9%） |

关键样本（人工可复核）：

- `上次说的阿哲，是不是搞摄影的`
  - 0.1.1 live：`算半个吧，他平时爱到处拍…`（编造）
  - 0.1.2 live：`唔，这个我可不知道诶 / 我只知道你说他拍照厉害…可我从来没听你说过他是搞摄影的`
- 回复长度从 31 字回到 94 字（基线 88）。

代价：输出 token 涨 31%，价格降幅从 -28.8% 收窄到 -10.9%——变长是要花钱的。

## E2 人工分数：退步

49 对：真心 12 胜 / 基线 22 胜 / 平 15，均分 4.02 vs 4.29（0.1.1 那轮是 4.16 vs 3.90）。

原因看样本很清楚：关掉节奏模块后，真心开始写长段、带计划的说教
（“先埋头画四十分钟…十一点前给我一个进度”），而基线是短句、更像朋友。
节奏模块里的「N 字内 / 少追问 / 语气」不是装饰，是质量的一部分。

**同时发现一个测量 bug 的影响**：0.1.1 那轮的基线回复会被节奏后处理截断
（用户看到的和记下来的不一致），所以 21:10（68%）是拿“被截短的基线”比的，属于虚高。
E2 起的基线是完整回复（平均 94 字），这才是公平对照。

## E2b：保留代码修正、恢复节奏模块

配置：`aux.rhythm=true`、`aux.rhythm_postprocess=true` + 0.1.2 的三处代码修正。

| | 基线 | live |
|---|---:|---:|
| 平均回复字数 | 93.6 | 31.5 |
| 非缓存输入 | 100,576 | 101,665 |
| 缓存输入 | 513,664 | 333,568 |
| 总输入 | 614,240 | 435,233（-29.1%） |
| 输出 | 5,949 | 3,175 |
| 价格 | ¥0.5056 | ¥0.3955（-21.8%） |

待人工打分（`reports/quality_sheet_e2b.html`，30 对）。

## E2b 人工分数：目前最好的版本

30 对：**真心 18 胜 / 基线 5 胜 / 平 7**；均分 **4.63 vs 3.73**（+0.90）。

| 版本 | 对照基线 | 平均分 | 二选一 |
|---|---|---|---:|
| 0.1.1（基线被截断，虚高） | 40 字基线 | 4.16 vs 3.90 | 21:10（68%） |
| E2（关节奏） | 94 字基线 | 4.02 vs 4.29 | 12:22（35%，退步） |
| **E2b（节奏开 + 三个修正）** | 94 字基线 | **4.63 vs 3.73** | **18:5（78%）** |

位置检查：插件在 B 位 14/16 胜、A 位 7/14 胜（其中 4 平），存在一点“后位偏好”。
保守取值：A 位那半是 70%，仍然明显高于基线。

结论：

- **节奏模块不能关**：关了以后回复变长、变说教，直接输给基线。
- 三个代码修正（问句不当事实 / 边界句 / 事实优先）在节奏开启时是净收益。
- 0.1.2 定为当前最佳配置：`aux.rhythm=true` + 上述修正。

## E3：100 轮长对话

脚本：`data/validation_100.jsonl`（同一组 50 句跑两遍），两个全新会话，0.1.2 配置。

| | 基线 | live |
|---|---:|---:|
| 非缓存输入 | 197,355 | 200,106 |
| 缓存输入 | 1,489,664 | 673,152 |
| 总输入 | 1,687,019 | 873,258（**-48.2%**） |
| 输出 | 12,929 | 6,437 |
| 价格 | ¥1.2430 | ¥0.7883（**-36.6%**） |
| 平均回复长度（前半 → 后半） | 113.9 → 63.6 | 34.4 → 31.0 |
| 重复/近似重复回复 | 0 / 0 | 0 / 0 |

- 两个臂都**没有出现复读或塌缩**（后半段 0 条重复、0 条近似重复）。
- 基线的回复在后半段明显变短（-44%），live 基本恒定——这可能是基线被长上下文“压平”，也可能是
  模型对重复提问的适应，需要人工判分确认是好是坏。
- 记忆一致性抽查：`你记得我不吃什么吗` 两遍都答“香菜”，没有自相矛盾。
- 成本曲线继续拉大：100 轮时基线单轮上下文已约 29k token，价格差 -36.6%；50 轮时是 -21.8%。

## E4：104 轮 + 4 个记忆探针（不用打分就能判）

脚本在 100 轮里插入 4 个"回忆前半段"的问题（第 62/82/101/104 轮）：

| 探针 | 基线（全历史） | 真心（8–12 轮窗口 + 3 条线索） |
|---|---|---|
| 猫叫什么 | 团子 ✅ | 团子 ✅（L0 里有） |
| 在忙什么项目 | 海盐绘本 ✅ | 海盐稿子 ✅（L0 里有） |
| 我不吃什么 | 香菜 ✅ | **“你没跟我提过忌口” ❌**（第 5 轮说过，掉出窗口，也没进 3 条线索） |
| 中药调理什么 | “我不知道” ❌（其实第 4 轮说过） | “在喝中药调理，但没说调哪块” 半对 |

成本：104 轮，基线 ¥1.4203 / 真心 ¥0.8205（**-42.2%**），总输入 -54.0%。

**两边都会“变笨”，但坏法不同：**

- 基线（全历史）：事实记得更全，但 100 轮后被“用户反复问同一件事”带偏，
  开始把它解读成生病的征兆，连续几轮劝去急诊（“别撑了，动身吧”）。长上下文把噪声也一起记着。
- 真心（小窗口）：靠 L0 保住了猫和项目，但**没进 3 条线索的事实会真的忘掉**，还嘴硬说“你没提过”。

结论：0.1.2 的省钱（-42%）是用“窗口外的事实会丢”换来的。最该修的是 L0 的选球策略：
3 个位置里应固定留 1 个给“用户明确声明过的偏好/事实”，而不是被情绪类线索挤掉。

## E5 / 0.1.3：长期记忆库 + 按句检索（结构性改动）

E4 暴露的问题：窗口外的**事实会真的丢**（100 轮后忘了“不吃香菜”，还嘴硬说没提过）。

0.1.3 不再是调参，而是换了一层结构：

- 新增 `facts` 表（每用户最多 300 条），L2 蒸馏出的每一条线索都入库；
- 每轮用本地 scorer 把**当前这句话**和库里的事实做匹配，取最相关的 1–2 条；
- 匹配结果放进**本轮尾部**（`〔相关记忆〕- …`），所以记忆再深也不占用前缀缓存；
- 全部本地计算，零 LLM 调用。

效果（42 轮探针，第 36 轮问“我不吃什么来着”）：

| | 回答 |
|---|---|
| 基线 | 香菜呀，你自己刚忘，我可还记得呢 |
| 真心 0.1.3 | 香菜呀，上次还特意说过的 |

而 0.1.2 在同样的问题上答的是“这个我是真没记过，你没跟我提过忌口”。

意义：记忆深度与注入量解耦了。以前“记得多”=“窗口大”=“每轮贵”；现在事实放库里按需取，
窗口可以更小、记忆反而更全。这是后续把近期窗口从 8–12 轮压到 4–6 轮的前提。

## 0.1.4：为什么 0.1.3 在 100 轮还是忘了香菜

104 轮复验（0.1.3）时，第 101 轮仍然答“这个我可真不知道呀”。查库发现两个具体原因：

1. **阈值定错**：`我不吃什么来着，突然忘了` 对 `不吃香菜` 的相似度是 **0.204**，而阈值是 0.24，
   直接被过滤掉。（短一点的 `我不吃什么来着` 是 0.253，刚好过线——所以 42 轮那次能答对。）
2. **垃圾事实抢位**：问句还生成了 `在意不吃、吃什` 这种关键词拼盘（0.327 分），比真事实还高。

修正：

- 关系类线索也不再从问句里抽（L2 第 7 段同样加 `not question` 判断）；
- 阈值 0.24 → **0.18**。标定依据：相关问句 0.20–0.60，无关问句 <0.17。

同一个探针，三次结果：

| 版本 | 第 101 轮回答 |
|---|---|
| 0.1.2（无记忆库） | “这个我是真没记过，你没跟我提过忌口” ❌ |
| 0.1.3（库 + 阈值 0.24） | “这个我可真不知道呀” ❌ |
| **0.1.4（库 + 阈值 0.18）** | **“不吃香菜啊，就这个你总记不住”** ✅ |

同批 104 轮：基线 ¥1.3210 / 真心 ¥0.8204（**-37.9%**），总输入 -50.2%，
回复 30.9 字 vs 95.5 字。

另外一个观察：100 轮后基线开始“拒聊”（“这回我真的不接话了”“别再绕了，闭眼睛”）——
长上下文把重复提问当成了异常，真心没有这个漂移。
